# W1 讲义：窗口程序的原理

> 先理解「为什么是这样」，再看代码，模板才有意义。
> 一句话总结：**窗口程序不是"我按顺序做"，而是"我等着，你操作，我响应"。**

---

## 一、和命令行程序的根本区别

### 命令行：顺序执行，一条接一条

```
开始
  ↓ 读输入
  ↓ 算
  ↓ 输出
  ↓ 结束（进程退出）
```

**程序自己决定什么时候做什么，做完就死。**

### 窗口：事件驱动，等着被叫

```
开始
  ↓ 造一个窗口
  ↓ 进入循环 ──────────────┐
  ↑                        │
  │  系统发来消息           │
  │  （点鼠标、按键、重绘）  │
  └── 你的函数处理 ─────────┘
        ↓ 只有收到"关闭"消息才跳出循环
      结束
```

**★ 关键转变：程序不再"主动往下走"，而是"停在那里等你"。你的代码不是按顺序执行的，是被**事件**唤醒一遍遍执行的。**

## 二、五个必须搞懂的概念

### 1. 句柄（HWND / HINSTANCE）—— 不是对象，是编号

**Windows 从不把窗口对象交给你。它给你一个编号，说"要操作那个窗口，报这个号"。**

```cpp
HWND hwnd = CreateWindowExW(...);   // hwnd 只是个编号（一个整数）
ShowWindow(hwnd, ...);              // "麻烦把 0x000A1234 号窗口显示出来"
```

**★ 比喻：去澡堂存衣服，你拿的是一个**牌子**，不是那个柜子。你要取东西，报牌子号。**

**★ 为什么这样设计：窗口对象是系统内部的复杂结构，直接让你操作会崩；用编号，系统每次都能检查"这个号还活着吗"。**

### 2. 窗口类 vs 窗口实例 —— 蓝图 vs 房子

**`WNDCLASSW` 是"窗口类型"的描述：这种窗口长什么样、鼠标是什么、**有事找谁**。**

**`CreateWindowExW` 是按这份描述**造一个具体的窗口**。**

```
WNDCLASSW（蓝图）      →  可以造无数个窗口
"我要一种窗口，           └─ 窗口A
 标题栏标准、               └─ 窗口B
 有事找 WndProc 函数"        └─ 窗口C
```

**★ 为什么要有"类"：因为造 100 个同样风格的窗口时，样式和消息处理只需要描述一次。这是"模板/类"思想的最早形态。**

### 3. 窗口过程（WndProc）—— 系统反过来调你

**这是整个 GUI 编程的核心，也是第一次遇到「别人调你的函数」。**

```cpp
LRESULT CALLBACK WndProc(HWND hwnd, UINT msg, WPARAM wParam, LPARAM lParam)
//                     ↑        ↑          ↑             ↑
//                  哪个窗口   发生了什么   附加信息1     附加信息2
```

**为什么必须是这个签名？因为**系统要按固定的格式调用你**——它不知道你的函数叫什么，只能按约定：**

```
系统：喂，第 4 个参数我给你了，第 1 个参数是窗口号，第 2 个是消息号……
    你按这个顺序收，我按这个顺序给。
```

**★ 你只是"填"进这套约定里。这就是**回调（callback）**：你写函数，但由别人在合适的时机调用。**

**★ `CALLBACK` 这个宏的意思是"按 Windows 约定的调用方式"，不是普通 C++ 函数调用。写窗口程序必须加。**

### 4. 消息 —— 一张写着"发生了什么"的便条

**消息就是三个数字：**

| 参数 | 含义 | 例子 |
|---|---|---|
| `msg` | **发生了什么**（一个编号） | `WM_DESTROY`=窗口被销毁、`WM_PAINT`=该重绘了、`WM_KEYDOWN`=按键了 |
| `wParam` | 附加信息 1 | 按键消息里，它是**哪个键**的编号 |
| `lParam` | 附加信息 2 | 按键消息里，它是**重复次数、扫描码** |

**★ 为什么用数字而不是对象：简单、跨进程、几十年不变。你只要 `switch` 或 `if` 判断 `msg` 等于几，就知道该干什么。**

**★★ 系统为什么不能自己处理？因为它不知道你想怎么反应。**窗口被点击了，可能是要退出、可能是要弹菜单——只有你知道。所以它只能发便条问你。**

### 5. 消息循环 —— 程序的心跳

```cpp
MSG msg;
while (GetMessageW(&msg, nullptr, 0, 0) > 0) {   // ① 去取一条消息，没有就等
    TranslateMessage(&msg);                      // ② 把按键加工成字符
    DispatchMessageW(&msg);                      // ③ 转交给对应的窗口过程
}
```

**这三行的意思：**

```
① 没有消息时，GetMessage 会让程序【睡着】，不占 CPU
② 有消息了，醒来
③ 分发给你写的 WndProc
④ 处理完，回去继续睡
```

**★ 所以窗口程序静止时 CPU 占用接近 0——它真的在睡，不是在空转。**

**★★ 这个循环只在收到 `WM_QUIT` 时返回 0 并结束。`WM_QUIT` 从哪来？就是 `WndProc` 里那句 `PostQuitMessage(0)`。**

## 三、为什么这里必须用「函数指针」和「结构体」

**这两个不是装饰，是这个机制的必要条件。**

### 函数指针：系统要"记住"你的函数

```cpp
wc.lpfnWndProc = WndProc;
//               ↑ 不是调用它，是把它的【地址】存起来
```

**★ 系统需要"将来某时刻打电话给你"，所以它保存的必须是你的**地址**，而不是现在调用一次。这就是函数指针的实际用途——**把一个函数当成值交给别人保管**。**

**★ 你之前只在术语表里见过"函数指针"，现在它有了真实用途：GUI 框架全靠它。**

### 结构体：一堆相关参数打包

```cpp
WNDCLASSW wc = {};
wc.lpfnWndProc   = WndProc;      // 有事找谁
wc.hInstance     = hInst;        // 属于哪个程序
wc.lpszClassName = CLASS;        // 这种窗口叫什么名字
wc.hCursor       = ...;          // 鼠标指针长什么样
wc.hbrBackground = ...;          // 背景什么颜色
```

**★ 造窗口需要七八个参数。如果写成 `RegisterClass(名字, 函数, 光标, 背景, ...)`，一是参数太多记不住，二是以后加参数就全崩。打包成结构体，加字段不影响老的调用。**

## 四、完整流程串起来

```
1. 你：注册一种窗口类型（蓝图里写着：有事找 WndProc）      RegisterClassW
2. 你：按蓝图造一个窗口，拿到句柄                          CreateWindowExW
3. 你：显示它                                            ShowWindow
4. 你：进入循环，开始睡觉                                 GetMessageW
5. 系统：有人拖动窗口 → 发 WM_PAINT 便条
6. 循环：醒来，把便条交给 WndProc
7. 你：WndProc 里处理 WM_PAINT（比如画一行字），返回
8. 回到第 4 步继续睡
9. 用户点关闭 → 系统发 WM_DESTROY
10. 你：在 WndProc 里 PostQuitMessage(0)
11. 循环：收到 WM_QUIT，跳出
12. main 返回，程序结束
```

**★ 第 10 步是你唯一"主动结束程序"的地方。不做这一步，窗口关了程序还在后台跑。**

## 五、常见误解

| 误解 | 真相 |
|---|---|
| 「`main` 里后面的代码会执行」 | **不会。消息循环是死循环，只有窗口关闭才跳出来，那时代码基本走到 `return 0` 了** |
| 「窗口关了程序就自动结束」 | **不一定。必须 `PostQuitMessage`，否则进程还在** |
| 「`WndProc` 是被 main 调用的」 | **不是。是系统调的，main 里根本看不到它被调用** |
| 「一个程序只能有一个窗口」 | **可以有无数个，共用同一个窗口类** |
| 「消息只能系统发」 | **你也能发：`SendMessage` / `PostMessage`，包括发给自己** |

## 六、这套设计的代价

**优点：**事件驱动能同时处理大量交互，不用你写轮询；系统统一管理绘制、焦点、输入法。

**代价：**样板代码多（注册、创建、循环、过程函数），一个空窗口就要 40 行。**这也是后来所有 GUI 框架（MFC、Qt、WinForms、Electron）存在的理由——它们都在帮你省这 40 行。**
