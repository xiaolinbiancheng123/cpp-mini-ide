# W1.5 讲义：键盘消息与多行绘制

> 目标：窗口能响应按键（按 ESC 关闭），并且能画出多行中文。
> 成品：`W1_第一个窗口\w1.5_window.cpp`

---

## 本节头文件

| 头文件 | 提供什么 |
|---|---|
| `<windows.h>` | 全部 Windows API（含 `WM_KEYDOWN`、`VK_ESCAPE`、`TextOutW`） |
| `<cwchar>` | `wcslen`（宽字符串长度） |

**★ 没有新增头文件——键盘消息和绘图都在 `windows.h` 里。**

---

## 一、`WM_KEYDOWN`：按键消息

**用户按下任意键时，系统发给窗口一条 `WM_KEYDOWN`。**

```cpp
case WM_KEYDOWN:
    if (wParam == VK_ESCAPE) {
        DestroyWindow(hwnd);
    }
    return 0;
```

| 参数 | 内容 |
|---|---|
| `wParam` | **虚拟键码**（Virtual Key），说明按的是哪个键 |
| `lParam` | 重复次数、扫描码、是否按住 Alt 等细节（初学不用管） |

### 常用虚拟键码

| 常量 | 键 |
|---|---|
| `VK_ESCAPE` | Esc |
| `VK_RETURN` | 回车 |
| `VK_SPACE` | 空格 |
| `VK_LEFT` / `VK_RIGHT` / `VK_UP` / `VK_DOWN` | 方向键 |
| `VK_F1` | F1 |

**★ 为什么不用字符判断？因为 Esc、方向键、F1 都不是"字符"，它们是**控制键**。`WM_KEYDOWN` 是**物理按键**层面的事件；`WM_CHAR` 才是"打出一个字符"（比如输入法敲了"你"）。**

## 二、`DestroyWindow` 与 `PostQuitMessage` 的分工

**这两个函数**不是**一回事：**

```cpp
DestroyWindow(hwnd);     // 销毁窗口 → 系统发 WM_DESTROY 给你的 WndProc
PostQuitMessage(0);      // 直接让消息循环退出
```

### ★★ 正确做法：按 ESC 时只调 `DestroyWindow`，**不要**直接 `PostQuitMessage`

**让流程走正常路径：**

```
用户按 ESC
  → 收到 WM_KEYDOWN
  → 调 DestroyWindow(hwnd)
  → 系统发 WM_DESTROY
  → WndProc 里已有的 PostQuitMessage(0)
  → 消息循环退出 → 进程结束
```

**★ 好处：不管用户点 ×（系统发 WM_CLOSE → 销毁）还是按 ESC（你主动销毁），**最后都汇集到同一个出口**。这叫"单一出口原则"。**

**★★ 如果按 ESC 直接 `PostQuitMessage`，就会跳过 `WM_DESTROY`。以后你要在关闭时保存配置、清理资源，就会漏掉 ESC 那条路径。**

## 三、字符串数组 + 循环画多行

```cpp
const wchar_t* lines[] = {
    L"欢迎使用这个窗口",
    L"按 ESC 可以关闭",
    L"（点右上角 × 也可以）",
};
int y = 30;
for (int i = 0; i < 3; i++) {
    TextOutW(dc, 30, y, lines[i], (int)wcslen(lines[i]));
    y += 40;
}
```

### `const wchar_t* lines[]` 是什么

**它的类型是"指向 `const wchar_t` 的指针"的**数组**——每个元素指向一个宽字符串。**

```
lines[0] ─→ L"欢迎使用这个窗口"
lines[1] ─→ L"按 ESC 可以关闭"
lines[2] ─→ L"（点右上角 × 也可以）"
```

**★ 和 `vector<string>` 是同一个思路：一排"字符串"。区别是这里用 C 的数组，长度固定、不占堆内存。**

### 循环里的三件事

| 代码 | 作用 |
|---|---|
| `TextOutW(dc, 30, y, ...)` | 在第 `y` 行画一句 |
| `y += 40` | 下一行往下挪 40 像素（行距） |
| `lines[i]` | 取第 i 个字符串 |

**★ `y` 是**纵坐标**，越小越靠上。`x=30` 固定不动，所以是竖着一列。**

---

## 四、本节踩过的坑（很典型）

| 错 | 现象 | 原因 |
|---|---|---|
| **`const wchar_t* lines[] = {}`** | `expected ',' or ';' before string constant` | `{}` 是**空数组**，元素跑到括号外面去了。要写 `= {` 开始装 |
| **元素之间没逗号** | 同上，报在第二个字符串前 | 数组元素必须用逗号分隔 |
| **`TextOutw`（小写 w）** | `'TextOutw' was not declared` | **C++ 区分大小写**，函数名是 `TextOutW` |
| **`Lines[i]`（大写 L）** | `'Lines' was not declared` | 声明的 `lines` 是小写 |
| **`wcslen` 不转 `(int)`** | `-Wconversion` 警告 | `wcslen` 返回 `size_t`，`TextOutW` 要 `int` |

**★ 这几条里有三条是**大小写/标点**，一条是**括号位置**——都是"编译器能抓"的错。真正危险的是下面这种它抓不到的。**

---

## 五、编译器抓不到的坑

### `WM_CREATE` 返回 -1 会让窗口创建失败

```cpp
case WM_CREATE:
    // ...
    return -1;    // ❌ CreateWindowExW 直接返回空，窗口根本没造出来
```

**★ 处理完 `WM_CREATE` 必须 `return 0;`。这条以后做控件时天天遇到。**

### 忘了 `return 0` 会"穿透"

```cpp
case WM_KEYDOWN:
    if (wParam == VK_ESCAPE) DestroyWindow(hwnd);
    // ← 忘了 return 0
case WM_PAINT:      // ← 按一下键就掉进绘图代码里
```

**★ 记住"直线 + 标记 + 剪刀"模型：switch 里是一条直线，`case` 是标记，`return`/`break` 是剪刀。**

---

## 六、本节结论

```
① 按键 → WM_KEYDOWN → wParam 是虚拟键码
② 关窗 → DestroyWindow（让系统走 WM_DESTROY 统一出口）
③ 多行文字 → 字符串数组 + 循环改 y 坐标
④ 画图必须在 BeginPaint 和 EndPaint 之间
⑤ case 必须有 return/break 收尾
```
