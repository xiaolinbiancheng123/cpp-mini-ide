# W2 讲义：控件、消息与打车费计算器

> 目标：让窗口里有输入框、按钮、文字标签，按钮一按能算出结果。
> 成品：`W1_第一个窗口\w2_taximeter.cpp`（3 个输入框 + 按钮 + 结果标签）

---

## 本节头文件

| 头文件 | 提供什么 |
|---|---|
| `<windows.h>` | 全部控件 API（`CreateWindowExW`、`GetWindowTextW`、`SetWindowTextW`、`WM_COMMAND`） |
| `<cwchar>` | `wcstod`（宽字符串转 double） |
| `<cstdio>` | `swprintf`（把数字格式化成字符串） |

**★ 控件不需要额外的库，也不需要注册窗口类——`EDIT`/`BUTTON`/`STATIC` 是**系统内置的窗口类**。**

---

## 一、控件 = 子窗口

**窗口里还能再放窗口，这些"窗口里的窗口"就叫控件。**

| 类名 | 长什么样 | 用途 |
|---|---|---|
| `L"EDIT"` | 可输入的框 | 填数字、文字 |
| `L"BUTTON"` | 按钮 | 点击触发动作 |
| `L"STATIC"` | 一行文字（不可编辑） | 标签、显示结果 |

**★ 它们和主窗口的唯一区别：多了 `WS_CHILD` 样式，并且父窗口必须是主窗口。**

---

## 二、`CreateWindowExW` 参数对照

**同一个函数，造主窗口和造控件，参数含义不同：**

| 参数 | 造主窗口 | 造控件 |
|---|---|---|
| 第 1 个 | `0`（扩展样式） | `0` |
| 第 2 个 | 你注册的类名 `CLASS` | **内置类名** `L"EDIT"` / `L"BUTTON"` / `L"STATIC"` |
| 第 3 个 | 窗口标题 | 控件上显示的文字 |
| 第 4 个 | `WS_OVERLAPPEDWINDOW` | **`WS_CHILD \| WS_VISIBLE`**（+ `WS_BORDER`） |
| 5–8 | x, y, 宽, 高 | 同左（相对父窗口客户区） |
| 第 9 个 | `nullptr`（菜单） | **父窗口句柄 `hwnd`** |
| 第 10 个 | `nullptr` | **`(HMENU)控件ID`** |
| 第 11 个 | `hInst` | `GetModuleHandleW(nullptr)` |
| 第 12 个 | `nullptr` | `nullptr` |

### 三个必须记住的点

```
① 必须带 WS_CHILD —— 否则控件变成一个独立的顶层窗口
② 必须带 WS_VISIBLE —— 否则控件创建了但看不见
③ 第 10 个参数 (HMENU)ID —— 控件 ID，以后靠它认人
```

**★ `(HMENU)101` 这个强转是历史包袱：当年这个参数位置是给菜单用的，后来改成能塞控件 ID 了。**

## 三、控件样式（`WS_` / `ES_` / `BS_` / `SS_`）

| 前缀 | 作用域 | 常用值 |
|---|---|---|
| `WS_` | 所有窗口通用 | `WS_CHILD`（子窗口）、`WS_VISIBLE`（可见）、`WS_BORDER`（细边框） |
| `ES_` | 输入框专属 | `ES_NUMBER`（只许数字）、`ES_PASSWORD`（显示圆点）、`ES_AUTOHSCROLL`（自动横向滚动） |
| `BS_` | 按钮专属 | `BS_CHECKBOX`（复选框）、`BS_RADIOBUTTON`（单选） |
| `SS_` | 静态文本专属 | `SS_CENTER`（居中）、`SS_SUNKEN`（凹陷） |

**★ `ES_NUMBER` 的坑：它连**小数点都不让输入**，所以「公里数」「单价」这种要小数的框不能加，只有「等待分钟」这种整数才能加。**
**★★ 而且它挡不住**粘贴**，只是体验优化，不是安全措施。**

## 四、控件 ID 与全局句柄

```cpp
#define ID_KM      101
#define ID_WAIT    102
#define ID_BTN     103
#define ID_RESULT  104
#define ID_GONGLI  105

HWND g_editKm    = nullptr;
HWND g_editWait  = nullptr;
HWND g_editGongli= nullptr;
HWND g_btnCalc   = nullptr;
HWND g_result    = nullptr;
```

**为什么控件句柄要放全局？**

```
WM_CREATE 里创建控件 → 句柄要存起来
WM_COMMAND 里要用它们 → 两个 case 之间没法传局部变量
→ 只能放全局
```

**★ `#define` 后**不加分号**；全局变量写在函数外面。**
**★ 纯文字标签（不参与计算）不需要保存句柄。**

---

## 五、`WM_CREATE`：窗口创建时摆控件

```cpp
case WM_CREATE:
{
    g_editKm = CreateWindowExW(...);
    // ... 其他控件
    return 0;      // ★ 必须 0
}
```

**★★ 返回 -1（或任何非 0）会让 `CreateWindowExW` 直接失败——窗口根本造不出来，而且不会报错，只会返回空句柄。这是最隐蔽的坑之一。**

---

## 六、`WM_COMMAND`：按钮被点击的消息

**点按钮 → 系统给父窗口发 `WM_COMMAND`。**

```cpp
case WM_COMMAND:
{
    if (LOWORD(wParam) == ID_BTN)     // 哪个控件发的
    {
        // 读输入 → 计算 → 写结果
    }
    return 0;                          // 剪刀：统一出口
}
```

**★ `wParam` 里塞了两个信息，用宏拆：**

| 宏 | 取出什么 |
|---|---|
| `LOWORD(wParam)` | 控件 ID（低 16 位） |
| `HIWORD(wParam)` | 通知码（`BN_CLICKED` = 按钮被点） |

**★ `LOWORD`/`HIWORD` = 取一个整数的低/高 16 位。**这就是为什么 `case` 里声明变量必须用 `{ }` 包起来——不然会报 `crosses initialization`。**

## 七、读写控件 + 数字转换

```cpp
// ① 读：从控件读到缓冲区
wchar_t bufKm[32];
GetWindowTextW(g_editKm, bufKm, 32);
//             从哪读    读到哪   最多几个字符

// ② 转：宽字符串 → double
double km = wcstod(bufKm, nullptr);

// ③ 算：业务逻辑
double total = 10.0 + lichengfei + dengdaifei;

// ④ 拼：数字转成文字
wchar_t out[64];
swprintf(out, 64, L"总价：%.2f元", total);

// ⑤ 写：写回标签
SetWindowTextW(g_result, out);
```

**★ `%.2f` = 保留两位小数。`64` 是缓冲区上限，防溢出。**
**★ 每个变量的角色：`g_editKm` 是"从哪"，`bufKm` 是"装到哪"，`km` 是"算的值"。**

## 八、输入校验（W2.5 加的）

```cpp
double gongli = wcstod(bufGongli, nullptr);
if (gongli <= 0.0)
{
    SetWindowTextW(g_result, L"每公里价格必须大于 0");
    return 0;
}
```

**★ 空输入/非数字 → `wcstod` 返回 0 → 被这条挡下来。**
**★★ 更严格的写法是用 `wcstod` 第二个参数判断是否"一个字符都没解析出来"：**

```cpp
wchar_t* end = nullptr;
double km = wcstod(bufKm, &end);
if (end == bufKm) { /* 输入根本不是数字 */ }
```

**★ 原则：用户会输入任何东西，不能假设输入是对的。**

## 九、本节踩过的坑

| 坑 | 症状 | 原因 |
|---|---|---|
| **控件创建写在全局作用域** | `'g_editKm' does not name a type` | 文件顶层只能写声明，**不能写语句** |
| **把 main 里主窗口创建改成控件创建** | `'hwnd' was not declared` | 顺序：先建主窗口拿到 `hwnd`，才能拿它当父窗口 |
| **`GetModuleHandieW`** | `not declared in this scope` | 拼写：`Handle` 不是 `Handie` |
| **`case` 里声明变量没加 `{}`** | `jump to case label` / `crosses initialization` | 后面的 `case` 会"跳过初始化"，C++ 禁止 |
| **两个输入框坐标重叠** | 界面上控件叠在一起 | 算清楚 y + 高度，别让区间相交 |
| **`WM_CREATE` 返回非 0** | 窗口创建失败，无报错 | 必须 `return 0;` |
| **`WM_COMMAND` 里 `return 0` 位置错** | 点按钮没反应 | `if` 没写 `{}` 时，`return` 成了 if 的唯一语句 |

## 十、验收方法（重要工程经验）

**★ 这次验收踩了一个大坑：用外部程序 `SetWindowText` 往输入框里写测试数据，**没生效**，导致结果一直是 10.00，我误判成程序有 bug。**

**★★ 可靠的验收方式：**

```
① 【预填法】在 WM_CREATE 里写死 SetWindowTextW(...)，然后发 WM_COMMAND
   → 适合自动化测试
② 【模拟键盘】SendInput 真的打字进去
   → 最接近真实用户，但 setup 复杂
③ 【人工点】自己输、自己点
   → 最简单，也不可替代
```

**★ 结论：跨进程操作别的程序的控件不可靠，别把它当验证手段。**

---

## 十一、本节结论

```
① 控件 = 加了 WS_CHILD 的子窗口，类名是内置的 EDIT/BUTTON/STATIC
② 控件 ID 用来在 WM_COMMAND 里认人（LOWORD(wParam)）
③ 控件句柄放全局，因为 WM_CREATE 和 WM_COMMAND 要用同一个
④ WM_CREATE 必须 return 0
⑤ 读输入 → wcstod → 算 → swprintf → SetWindowTextW 写回
⑥ case 里声明变量必须加 {}（剪刀模型）
⑦ 输入校验必须有，用户会输入任何东西
```

**★ 从这节课开始，程序不再是"演示"，而是**能用的工具**了。**
