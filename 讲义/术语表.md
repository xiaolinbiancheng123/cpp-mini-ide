# C++ 术语表

> 规则：**新术语第一次出现时，用一句话解释，并标上这里的名字。**
> 这里只写「人话解释 + 什么时候会碰到」，不写教科书定义。

---

## 一、语言基础

| 术语 | 人话解释 | 什么时候遇到 |
|---|---|---|
| **命名空间** | 给一堆名字加个前缀，避免重名。`std::cout` 的 `std` 就是命名空间名，`using namespace std;` 表示「后面的名字默认去 `std` 里找」 | 每个程序开头 |
| **字面量** | 直接写在代码里的固定值。`42`、`3.14`、`"你好"` 都是字面量，跟变量相对（变量是能变的） | 赋值时 |
| **语句** | 一条以分号结尾的指令。`int a = 1;` 是一条语句 | 到处 |
| **表达式** | 能算出一个值的写法。`a + 10` 是表达式，`a = a + 10` 也是（它算出一个值并赋回去） | 赋值、条件里 |
| **布尔** | 只有真/假两个值的类型，`bool`，写 `true` / `false` | 条件判断 |
| **字节** | 内存的最小单位，1 字节 = 8 位。`int` 占 4 字节，一个汉字在 UTF-8 里占 3 字节 | 算内存、算字数 |
| **作用域** | 一个变量「能用的范围」，通常是离它最近的那对 `{ }`。出了 `}` 就不存在了 | 写函数、写 if 块 |
| **强制类型转换** | 明确要求把值从一种类型变成另一种。`(double)n` 把 int 变 double | 做除法要小数时 |
| **函数指针** | 把「函数」本身当成一个值存起来、传给别人。C++ 里函数不是值，但函数指针是 | 还没学（Win32 窗口要用） |
| **回调函数** | 你写一个函数，但不主动调用它，交给别人（系统/库）在合适的时机来调 | 还没学（Win32 窗口要用） |

## 二、内存（最容易懵的一块）

| 术语 | 人话解释 | 什么时候遇到 |
|---|---|---|
| **栈（stack）** | 一块自动管理的小空间。函数里的普通变量、固定大小的数组放这儿，函数结束自动回收 | 说「数组在栈上」时 |
| **堆（heap）** | 一块需要手动申请/释放的大空间。`vector` 的元素、`new` 出来的东西放这儿 | 说「vector 要堆分配」时 |
| **指针** | 存「内存地址」的变量。`int* p = &a;` 意思是 p 里存着 a 的地址 | 还没学（L0-3 之后） |
| **野指针** | 指向已经失效/被回收的内存的指针。对它做任何操作都不可预测 | 还没学 |
| **未定义行为（UB）** | 标准没规定后果的操作。**不是「一定崩」，而是「什么都可能发生」**，可能崩、可能静默算错 | 数组越界、空 vector 取下标 |

**★ 为什么 UB 可怕：它在你的机器上「看起来正常」，换台机器/换个编译器就炸。**

## 三、容器与算法

| 术语 | 人话解释 | 什么时候遇到 |
|---|---|---|
| **容器** | 用来装一堆同类型数据的东西，统称容器。数组、`vector`、`map` 都是容器 | 存数据时 |
| **迭代器（iterator）** | 容器里「指向某个元素」的通用指针。用 `it != v.end()` 判断有没有走到头 | 遍历 `map` 时 |
| **哈希 / 哈希值** | 把一个值（比如字符串）算成一个整数，用来快速定位。`"小林"` → 某个整数 → 直接跳到对应位置 | `unordered_map` |
| **桶（bucket）** | 哈希表内部的一格。哈希值算出「该放第几格」，那一格就是桶 | 解释哈希表原理时 |
| **红黑树** | 一种自动保持平衡的二叉树。`map` 底层用它，所以能保证按 key 有序 | 解释 `map` 为什么有序时 |
| **O(1) / O(log n) / O(n)** | 描述「数据变多时，耗时怎么涨」。O(1)=不变，O(log n)=涨得极慢，O(n)=线性涨 | 谈性能时 |
| **连续内存** | 一堆元素挨着放在一起。数组和 vector 都是，所以能用「起始地址 + 下标」直接算出位置 | 解释数组为什么快 |
| **变长数组（VLA）** | 长度在运行时才决定的数组，`int a[n];`。**不是标准 C++**，是 gcc 的扩展 | 你的编译器实测过 |

## 四、字符串与编码

| 术语 | 人话解释 | 什么时候遇到 |
|---|---|---|
| **流（stream）** | 「数据像水流一样过来」的抽象。`cin` 是输入流，`cout` 是输出流，`ifstream` 是文件输入流 —— 它们的用法都一样（`>>`/`<<`） | 读输入、读文件 |
| **UTF-8 / GBK / 代码页** | 两种把文字变成字节的规则。UTF-8 一个汉字 3 字节，GBK 一个汉字 2 字节。代码页就是「当前用哪套规则」 | 中文乱码时 |
| **BOM** | 文件开头三个隐藏字节，用来标记「这是 UTF-8」。PowerShell 写 .ps1 时经常踩到 | 写脚本时 |
| **有效数字** | 一个数里「真正可信的位数」。`float` 约 7 位，`double` 约 16 位 | 讲精度时 |
| **容差** | 判断两个小数相等时允许的误差范围。浮点数永远不要用 `==`，要用「差 < 1e-9」 | 比较小数 |

## 五、编译与工具

| 术语 | 人话解释 | 什么时候遇到 |
|---|---|---|
| **头文件** | 别人写好的接口清单。`#include <iostream>` 就是「把 iostream 的清单抄进来」 | 每个程序开头 |
| **预处理** | 编译前先做的一轮文本替换。`#include` 就是预处理指令，它把整个头文件**原样抄进**你的 .cpp。每次编译都从头抄一遍，没有缓存 | 看到 `#` 开头 |
| **预编译头（PCH）** | 一种**手动配置**的优化：把常用头文件提前处理成二进制缓存，减少每次编译的重复劳动。只影响**速度**，不影响正确性 | 大项目才用（`pch.h`） |
| **IntelliSense** | VS Code 的代码分析引擎。它有自己的索引过程，**没索引完时会显示红色波浪线，但那不是编译错误** | 刚打开文件时看到满屏红 |
| **编译** | 把 .cpp 翻成机器码。**语法错在这一步报** | 按 F11 / Ctrl+Shift+B |
| **链接** | 把编译产物和库拼在一起。**「undefined reference」这类错在这一步报** | 忘了链接 `-luser32` 时 |
| **编译器扩展** | 编译器自己加的、标准里没有的功能。gcc 允许 `int a[n]`，但标准不许 | 换编译器就崩的代码 |
| **`-pedantic-errors`** | 让编译器严格按标准检查，不许用扩展 | 检查代码是否合规 |
| **GUI 子系统 / 控制台子系统** | Windows 把程序分两类：有黑窗口的（console）和没黑窗口的（GUI）。`-mwindows` 指定后者 | 写窗口程序 |

## 六、Windows 平台

| 术语 | 人话解释 | 什么时候遇到 |
|---|---|---|
| **句柄（HWND）** | Windows 给你的一个编号，代表「某个窗口」。你不直接碰窗口对象，只通过这个编号操作 | 写窗口程序 |
| **窗口过程（WndProc）** | 你写的一个函数，系统每次有消息（点了、按键了、要重绘）就调它一次 | 写窗口程序 |
| **消息循环** | 一个 `while` 循环，不断从系统取消息、分发出去。程序靠它「活着」 | 写窗口程序 |
| **`Sleep`** | Windows 的睡眠函数，单位毫秒，大写 S | 想让程序停一下 |
| **`system()`** | 调用系统的命令行。`system("pause")`、`system("chcp 65001")` 都是借系统的工具 | 双击 exe 时防闪退 |
